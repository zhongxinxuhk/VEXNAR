# 桌面会话与项目侧栏实施方案

## 核对依据

Codex 桌面侧栏接口报告 `project` 分组、项目及普通会话按更新时间排序、置顶采用独立手动顺序。项目目录和会话列表分别返回，近期会话可以没有项目归属。有些 Codex 交互不会由只读接口返回，本方案据此落实与这些约束一致的 VEXNAR 行为。

## 当前问题

1. 注册项目必须有普通会话才显示，空项目和仅剩置顶会话的项目都会消失。
2. 置顶会随消息更新重新排序。项目排序将本机编辑目录强行置顶。
3. 全局新聊天沿用本机编辑目录，立刻写入空行，打开新聊天还可能停止当前回合。切换目录通过创建会话完成，选择目录产生空记录。
4. 工作区下拉从聊天列表反推项目，缺少空项目和显式的「未选择工作区」。对话标题可能回显与该会话无关的全局目录。
5. 删除最后一条会话会创建一个新的空会话。两个会话行实现各自处理相同动作，导航行为容易偏离。

## 实施方案

- PostgreSQL 已注册项目和会话的 `project_id` 是分组依据。有项目 ID 的普通会话只显示在该项目里。无项目 ID 的普通会话只显示在「最近」，置顶会话只显示在「置顶」。注册项目总是显示，项目按所属会话的最近更新时间排序，支持按名称切换。
- 置顶列表采用独立的显示顺序，初次由后端 `pinned_at` 初始化。桌面可上移或下移，显示偏好本机保存。
- 全局「新聊天」进入未选择工作区的草稿。项目行上的「新聊天」进入该项目的草稿。每个目标目录的未发送草稿独立保存，首次发送才通过现有 Go 接口创建会话。切换视图、选择工作区和打开旧会话均保留原会话归属，不停止其后台回合。
- 工作区下拉从已注册项目读取，包括空项目。选择「未选择工作区」回到独立草稿。添加项目调用现有后端注册接口，空项目可立即出现。删除最后一条会话返回空草稿。
- 共用会话行显示与动作。搜索使用会话标题、项目名和保存的工作区；页头只展示当前会话或当前草稿的工作区。

## 验收

用纯逻辑测试覆盖分组、排序、空项目和置顶顺序；用 Electron 固定后端夹具验证添加项目、项目与独立草稿切换、首条消息创建、原会话归属和侧栏导航。再运行桌面类型检查及全部桌面测试。

## 实施验收结果

桌面类型检查、14 个测试文件共 122 项测试、Electron 界面回归及 `git diff --check` 通过。Electron 夹具验证了空项目注册、项目与独立草稿隔离、首次发送才创建会话、项目归属不变以及切换草稿不会停止后台回合。本地 PostgreSQL 17 上的 4 项 Go 回归覆盖项目路由、回环认证、归属和置顶排序。
